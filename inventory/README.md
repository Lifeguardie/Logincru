# מערכת ספירת מלאי למסעדה

מחליפה את דפי הספירה המודפסים: סופרים בטלפון, הנתונים נשמרים בשרת,
ומקבלים שווי מלאי והיסטוריה שאפשר להשוות.

מערכת **עצמאית לחלוטין** — מסד נתונים משלה, משתמשים משלה, פורט משלה.
היא לא נוגעת בשום מערכת אחרת.

---

## יחידות מידה ותמחור

זו הנקודה החשובה במערכת. במסעדה יש שלושה מצבים שונים, וכולם עובדים:

| מצב | דוגמה | איך סופרים | איך מתומחר |
|---|---|---|---|
| מתומחר ונספר ביחידות | בקבוק בירה | 24 יחידות | 4.50 ₪ ליחידה |
| **מתומחר בקילו, נספר ביחידות** | שניצל קפוא | 40 יחידות | 45 ₪ לק"ג, יחידה = 0.180 ק"ג |
| מתומחר בקילו, נשקל | עגבניות | 12.4 ק"ג | 8 ₪ לק"ג |

### איך זה מוגדר

לכל פריט יש:

- **יחידת בסיס** (`kg` / `liter` / `unit`) — יחידת החישוב של הפריט
- **מחיר ליחידת בסיס** — אם יחידת הבסיס היא ק"ג, זה **המחיר לקילו**
- **יחידות ספירה** — כל דרך שבה מותר לספור את הפריט, עם **מקדם**:
  כמה יחידות בסיס יש ביחידת ספירה אחת

**דוגמה — שניצל:** יחידת בסיס `ק"ג`, מחיר `45 ₪`.

| יחידת ספירה | מקדם | כלומר |
|---|---|---|
| ק"ג | 1.0 | קילו אחד |
| יחידה | 0.180 | שניצל אחד שוקל 180 גרם |
| ארגז | 5.0 | ארגז שוקל 5 ק"ג |

ספירה של **2 ארגזים + 7 יחידות** = `2×5.0 + 7×0.180` = **11.26 ק"ג** = **506.70 ₪**.

### שלושה דברים שחשוב לדעת

1. **אפשר לספור אותו פריט בכמה יחידות באותו אזור.** בבר יש 3 בקבוקים
   סגורים ובקבוק פתוח ששוקל 400 גרם — שתי הזנות, פריט אחד, והמערכת
   מסכמת. במסך הספירה כל היחידות מוצגות זו לצד זו.

2. **כמויות עשרוניות מותרות בכל מקום.** "חצי ארגז" ו-2.4 ק"ג הם קלט תקין.

3. **משקל אריזה (טרה).** ליחידת שקילה אפשר להגדיר את משקל המיכל הריק,
   והמערכת מנכה אותו אוטומטית. בלי זה משקל הפלסטיק נספר כמלאי.

### מחירים היסטוריים

המקדם והמחיר נשמרים בשורת הספירה כתמונת מצב. **עדכון מחיר בקטלוג לא
משנה ספירות שכבר נסגרו** — ספירה מלפני חודשיים תמשיך להראות את השווי
שהיה נכון אז.

## התקנה

דרישות: Node.js 20 ומעלה, MariaDB 10.4 / MySQL 8 ומעלה.

```bash
cd inventory
npm install
cp .env.example .env
```

ערוך את `.env`:

```bash
# חובה להחליף - צור סוד אקראי:
openssl rand -hex 32
```

הרץ מיגרציות ונתוני התחלה:

```bash
npm run migrate          # יוצר את מסד הנתונים והטבלאות
npm run seed             # אזורים, מחלקות, ומשתמש מנהל
npm run seed -- --demo   # בנוסף: פריטי דוגמה שמדגימים את כל מצבי התמחור
```

ה-seed יוצר משתמש `admin` עם סיסמה `admin1234`.
**יש להחליף אותה מיד.** אפשר לשלוט בזה מראש:

```bash
SEED_ADMIN_USER=meir SEED_ADMIN_PASSWORD='...' npm run seed
```

בנה את הלקוח והפעל:

```bash
npm run build:client
npm start                          # פיתוח
pm2 start ecosystem.config.js      # פרודקשן
```

השרת מגיש גם את ה-API וגם את הממשק מאותו פורט (ברירת מחדל 4010).

### פיתוח עם רענון חי

```bash
npm run dev                     # שרת על 4010
npm --prefix client run dev     # לקוח על 5173, עם proxy ל-API
```

## שימוש

1. **פתיחת ספירה** — מנהל פותח ספירה חדשה. יכולה להיות ספירה פתוחה אחת בלבד.
2. **ספירה** — כל סופר בוחר אזור ומזין כמויות. מסך אחד לכל אזור, בסדר של הדף.
3. **סגירה** — מנהל סוגר, והשווי הכולל מקובע.
4. **רכש** — רושמים את הקניות שבין הספירות.
5. **דוח צריכה** — `מלאי פתיחה + רכש − מלאי סגירה`.

### הרשאות

| תפקיד | מה מותר |
|---|---|
| `counter` | לצפות בקטלוג, ולהזין שורות ספירה |
| `manager` | בנוסף: קטלוג, מחירים, יחידות, פתיחה וסגירת ספירות, רכש, דוחות |
| `admin` | בנוסף: ניהול משתמשים |

### עבודה בלי קליטה

במחסן ובמקררים אין רשת. כל הזנה נשמרת קודם מקומית בטלפון ורק אחר כך
נשלחת, ונמחקת מהתור רק אחרי שהשרת אישר אותה. חיווי בתחתית המסך מראה
כמה הזנות עדיין ממתינות. אפשר לסגור את האפליקציה באמצע — ההזנות יישלחו
לבד ברגע שתהיה רשת.

## ייבוא מאקסל

הייבוא הוא תמיד דו-שלבי: קודם תצוגה מקדימה שמראה בדיוק מה ייווצר ומה
יעודכן, ורק אחרי אישור נכתב משהו.

המערכת מזהה כותרות בעברית ובאנגלית:

| שדה | כותרות מזוהות |
|---|---|
| שם פריט (חובה) | `שם פריט`, `שם`, `פריט`, `name` |
| מק"ט | `מק"ט`, `מקט`, `קוד`, `sku` |
| מחלקה | `מחלקה`, `קטגוריה`, `category` |
| יחידת מידה | `יחידת מידה`, `יחידה`, `base unit` |
| מחיר | `מחיר`, `מחיר לקילו`, `עלות`, `price` |
| ספק | `ספק`, `supplier` |
| אזור | `אזור`, `מיקום`, `location` |

מחירים מתקבלים גם עם סימן שקל ופסיקים. תאריכים ברכש מתקבלים בפורמט
`DD/MM/YYYY` וגם כתאריך אקסל.

## מבנה

```
server/
  src/
    services/units.js      ← כל חישובי היחידות והשווי. נקודת האמת היחידה.
    services/valuation.js  שווי, השוואה בין ספירות, צריכה
    services/excel.js      ייבוא וייצוא
    routes/                auth, items, catalog, counts, purchases, imports, reports
    middleware/            אימות JWT, טיפול בשגיאות
  migrations/              SQL ממוספר, מורץ על ידי scripts/migrate.js
  tests/                   בדיקות יחידה על חישובי היחידות
client/
  src/lib/api.js           כל קריאה לשרת עוברת דרך כאן
  src/lib/queue.js         תור השמירה שעמיד לניתוקי רשת
  src/pages/               המסכים
```

npm test
